# Audit menyeluruh jalur AI (Edge Function + klien) — 2026-09-17 (v134)

Lingkup: semua yang berhubungan dengan AI di aplikasi ini — Edge Function
`analyze-finance` (4 mode) dan `scan-receipt` (Gemini vision), payload yang
dikirim klien, tempat API key berada, rate limiting, sanitasi, cache, penanganan
error, privasi data, dan cakupan uji. Melengkapi `docs/audit-edge-functions-2026-09-14.md`
(v125) yang memeriksa keberadaan/izin function; audit ini masuk ke isi kode.

Semua baris yang disebut adalah hasil pembacaan kode pada commit saat audit ini
ditulis. Yang TIDAK bisa saya verifikasi dari repo diberi tanda **[belum diverifikasi]**.

## 1. Peta jalur AI

| Fitur | Pemicu di klien | Mode di function | Balasan |
|---|---|---|---|
| Rekomendasi AI (dashboard) | **hanya tombol ⟳ manual** (`app.src.js:6431`) | tanpa `mode`/`question` | array insight JSON (maks 5) |
| Ringkasan Bulanan (Laporan) | manual (`app.src.js:6509`) | `mode: "monthly_summary"` | 1 paragraf |
| Tanya AI (Analisis) | kirim pertanyaan (`app.src.js:7610`) | ada `question` | teks bebas |
| Smart Categorization (form) | debounced saat mengetik | `mode: "suggest_category"` | `{kategori}` |
| Baca Struk (foto) | tombol scan struk | function `scan-receipt` | data transaksi |

Payload ringkasan dibangun di modul murni `src/domain/ai-summary.js`
(`buildFinanceSummaryForAI`), dipakai bersama oleh tiga mode pertama — itulah
sebabnya perbaikan v128 (anggaran sub-kategori) otomatis menutup tiga jalur.

## 2. Yang sudah sehat (tidak perlu tindakan)

- **API key Gemini tidak pernah menyentuh browser.** `GEMINI_API_KEY` dibaca
  lewat `Deno.env.get` di kedua function; klien hanya mengirim ringkasan +
  pertanyaan. Tidak ada `AIza…` di berkas klien (dikonfirmasi scan rahasia v132).
- **Auth berlapis.** Selain `verify_jwt=true` di platform **[belum diverifikasi
  live — sumber: komentar kode 2026-09-14]**, `analyze-finance` memverifikasi
  pemanggil sendiri: tanpa header `Authorization` → 401; `supabase.auth.getUser()`
  gagal → 401. Identitas user dipakai untuk rate limit per-user.
- **Rate limit server-side per mode** (`RATE_LIMITS`, RPC
  `check_and_consume_rate_limit` di `public.api_rate_limits`):
  `suggest_category` 60/jam, `insights` 20/jam, `monthly_summary` 20/jam,
  `question` 40/jam — ditambah jeda minimal 8 detik antar pesan Tanya AI (tabel
  `rate_limits`). Fail-open bila RPC-nya error: disengaja dan terdokumentasi.
- **Sanitasi output ketat** untuk insights: buang item tanpa `title`/`message`
  teks; `title` ≤ 80, `message` ≤ 500, `detail` ≤ 4000 karakter; `severity`
  dipaksa ke {info, warning, success}; dipotong maksimal 5 kartu. Ada fallback
  bila Gemini tidak membalas JSON murni.
- **Batas input** ada di beberapa tempat: `keterangan` ≤ 200 karakter,
  `categories` ≤ 100 item; `scan-receipt` membatasi base64 ±6 MB dan menolak
  tanpa `image_base64`.
- **Biaya terkendali by design**: Gemini **tidak pernah** dipanggil otomatis —
  hanya saat pengguna menekan tombol refresh. Hasilnya di-cache di
  `appSettings.ai_insight_cache` (kolom `settings`) sehingga ikut ke perangkat lain.

## 3. Temuan yang perlu tindakan (urut prioritas)

**T1 — `question` tidak dibatasi panjangnya.** `analyze-finance/index.ts:299`
menyisipkan `String(question).trim()` langsung ke prompt, tanpa `.slice()` —
bandingkan `keterangan` yang dipotong 200 karakter di baris 197. Dampak: prompt
bisa berukuran berapa pun → biaya token tak terduga dan risiko permintaan gagal;
satu-satunya pagar adalah rate limit 40/jam. Saran: potong (mis. 1.000–2.000
karakter) + balas 400 bila kosong, disertai uji.

**T2 — tidak ada `generationConfig` sama sekali** (dikonfirmasi: 0 kemunculan
`generationConfig`/`maxOutputTokens`/`temperature` di kedua function). Artinya:
(a) tidak ada pagu token keluaran → biaya tidak terpagar; (b) mode yang
mengharapkan JSON tidak memakai `responseMimeType: "application/json"`, sehingga
bergantung pada model + pembersihan ```json``` manual; (c) tanpa `temperature`
jawaban untuk data yang sama tidak stabil.

**T3 — tidak ada timeout pada panggilan Gemini.** Tidak ada `AbortController`/
`signal` di `callGemini` (maupun `scan-receipt`). Kalau Gemini menggantung,
function ikut menggantung sampai batas platform dan UI menunggu tanpa batas.

**T4 — pesan error internal diteruskan ke klien.** Kegagalan Gemini dibalas
`{ error: "Gagal memanggil Gemini API", detail: errText }` (502) — `errText`
mentah dari Google bisa memuat pesan kuota/ID permintaan; catch paling luar
membalas `String(e)` (500). Saran: catat detail di log server, balas pesan umum.

**T5 — cache klien tidak punya kedaluwarsa.** `saveCachedAiInsight()` menyimpan
`{ insights, timestamp }`, tetapi `loadCachedAiInsight()` hanya memeriksa
`Array.isArray(cached.insights)` — `timestamp` tidak pernah dibaca. Rekomendasi
bisa basi tanpa batas dan ikut tersinkron ke semua perangkat sampai pengguna
menekan ⟳. Pilihannya: pakai TTL (mis. 24 jam) atau hapus field yang menipu.

**T6 — dua klaim dokumentasi tidak cocok dengan kode.**
1. Komentar function menyebut fitur "terpanggil cukup sering (tiap dashboard
   dibuka / tiap ada transaksi baru, dengan jeda minimal 3 menit)". Kenyataannya
   klien **hanya** memanggil saat tombol refresh diklik (dan tidak ada jeda
   3 menit di klien).
2. Komentar "browser cuma mengirim RINGKASAN keuangan (angka agregat, bukan API
   key)" tidak lengkap: `src/domain/ai-summary.js:152-154` mengirim
   **`akun` (nama akun) dan `keterangan` (catatan bebas, dipotong 80 karakter)**
   untuk 3 transaksi terbesar (`transaksi_terbesar_bulan_ini`). Catatan transaksi
   bisa memuat informasi pribadi, dan itu dikirim ke penyedia AI pihak ketiga.
   Perlu dinyatakan terang-terangan (README/kebijakan privasi) atau dijadikan
   opsi yang bisa dimatikan.

**T7 — tidak ada uji yang mengeksekusi kode Edge Function.** 34 uji terkait AI
semuanya sisi klien dan semuanya lulus: `ai-summary` 16, `ai-recommendations-domain`
7, `ui-ai-recommendations` 5, `edge-service` 6. Logika di dalam function (rate
limit, sanitasi output, pembentukan prompt, pemetaan mode) tidak teruji sama
sekali — perubahan di sana hanya ketahuan setelah deploy.

**T8 — CORS `Access-Control-Allow-Origin: *`.** Dengan verifikasi JWT risikonya
rendah, tapi mempersempit ke origin aplikasi mengurangi permukaan.

## 4. Privasi data — apa yang sebenarnya keluar dari perangkat

| ikut dikirim ke Gemini | sumber | batas |
|---|---|---|
| angka agregat (pemasukan/pengeluaran/saldo/anggaran/persen/rata-rata/proyeksi) | `ai-summary.js` | — |
| nama kategori + jumlah + persen | `ai-summary.js:116-119` | top kategori |
| **nama akun** | `ai-summary.js:152` | 3 transaksi terbesar |
| **catatan transaksi (`keterangan`)** | `ai-summary.js:154` | 80 karakter, 3 transaksi |
| pertanyaan bebas pengguna | `app.src.js:7610` | **tanpa batas** (lihat T1) |
| foto struk (base64) | `scan-receipt` | ±6 MB |

Tidak ada API key, tidak ada email/password, tidak ada ID user yang dikirim ke
Gemini. Yang perlu keputusan pemilik hanya dua baris tebal di atas.

## 5. Rekomendasi urutan pengerjaan

1. **T1 + T2 + T3 sekaligus** di `analyze-finance` (dan `scan-receipt` untuk T3):
   batas `question`, `generationConfig` (`maxOutputTokens`, `responseMimeType`
   untuk mode JSON, `temperature` rendah), dan `AbortSignal.timeout(...)`.
   Perubahan kecil, langsung menurunkan risiko biaya & permintaan menggantung.
   **Wajib deploy ulang function** setelah diubah (`supabase functions deploy
   analyze-finance`) — tanpa itu perubahan tidak berlaku.
2. **T6**: perbaiki dua komentar/README, lalu putuskan apakah `keterangan`/`akun`
   tetap dikirim (keputusan produk/privasi, bukan teknis).
3. **T5**: TTL cache atau hapus `timestamp`.
4. **T7**: pindahkan logika yang bisa murni (sanitasi insights, pemetaan mode,
   pembentukan prompt) ke modul yang bisa diuji di Node, atau tambah `Deno test`.
5. **T4 + T8**: rapikan pesan error dan persempit CORS.
